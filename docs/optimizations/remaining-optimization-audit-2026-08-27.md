# Argus 优化审计与实施记录（2026-08-27）

> 本批次复核 2026-08-25 审计之后新增的回归闭环与诊断中心，聚焦确定性正确性和
> 资源隔离问题；未重复实施历史已完成项。

## 已完成

1. **诊断扫描预算严格化**
   - 原实现按候选文件总大小扣预算，但只要进入单个文件就会整文件读入，超大文件可绕过
     `scan_max_bytes`。
   - 改为在剩余预算内从文件尾部按字节读取完整日志行；到达上限返回
     `scanLimited=true`，单个大文件不再导致无界内存读取。

2. **日志游标轮转降级修复**
   - 原 `_EventMatcher` 只有找到精确行号后才会进入时间戳分支，游标文件丢失或截断时会
     永久跳过全部结果。
   - 新事件 ID/游标使用文件字节偏移和时间戳，查询前校验精确位置；失效时按“严格早于
     游标时间戳”继续扫描。旧行号事件 ID/游标继续兼容，无 REST/OpenAPI 变化。
   - 精确游标从对应偏移之前续页并跳过已读候选文件；游标校验计入扫描预算。详情与上下文
     改用定点或固定窗口流式读取，不再把整个日志文件重复加载到内存。

3. **回归详情轮询串行化**
   - 原 `setInterval` 在请求超过 3 秒时会产生重叠轮询，旧响应可能覆盖新状态。
   - 改为请求结束后再安排一次 `setTimeout`；打开、刷新、切换、关闭和卸载都会中止旧请求，
     请求代次校验继续作为兜底。

## 2026-08-31 补充完成

1. **回归终态汇总移出事件循环**
   - `TaskRunner` 的任务启动、状态读取和终态写入统一经现有 IO executor 执行并等待完成；
     回归批次推进随终态落盘在同一 IO 工作内完成，不新增脱离 Worker 生命周期的后台任务。
   - `RegressionService.handle_task_terminal` 增加结构化操作耗时日志，保留异常隔离和启动恢复
     兜底语义。
   - 复核修正：EventBus 在 Web/API 生命周期绑定 owner loop，IO 线程发布通过
     `call_soon_threadsafe` 回投，任务与回归终态事件继续实时通知 WebSocket；CLI 未绑定时仍
     降级写入 history。终态推进的操作日志在内部异常转换前记录，失败不会误报 success。
   - 回归批次创建、队列满回收和用户取消中的同步 SQLite/lifecycle 操作统一经 IO executor
     执行，避免大批次逐项处理阻塞事件循环。

2. **受保护 Blob 请求补齐超时与取消**
   - Blob 下载复用 API 请求的超时控制并接受 `AbortSignal`；超时与调用方取消分别返回稳定的
     `REQUEST_TIMEOUT`、`REQUEST_ABORTED` 错误码。
   - 鉴权图片在路径切换或卸载时释放等待；同路径并发消费者仍共享一次下载，只有最后一个
     等待者离开才取消底层请求。

3. **架构与审计文档同步**
   - 架构文档标记组合根收敛已完成，并清理已删除历史清单的失效引用。
