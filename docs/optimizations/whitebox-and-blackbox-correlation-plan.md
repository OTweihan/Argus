# 白盒能力补全与黑白盒关联实施计划

## 1. 背景与目标

当前白盒能力属于“后端最小可运行链路”：Python 已能解析源码、调用 Java 分析器并将结果映射为
Findings，但控制台没有白盒专用配置与结果展示；执行器未使用 Java 异步作业的进度能力；源码版本
和容器可见性未形成可审计输入；映射后的问题也丢失部分规则语义。黑盒浏览器执行与白盒端点、
调用流之间尚未建立关联。

本计划先把白盒补全为可独立使用的产品能力，再建立“浏览器行为证据 ↔ 后端源码证据”的关联。
完成后，回归测试闭环可以复用这些能力，但本计划不依赖回归批次功能才能交付。

### 成功标准

- 白盒任务使用类型化配置，不再要求用户手工填写通用参数键值对。
- 每次分析记录明确的源码来源、分支和 Git commit SHA，并在执行前验证 Python 与 Java 的源码可见性。
- Java 异步分析进度映射到 Argus 任务时间线，取消语义真实、可解释。
- 白盒报告完整展示诊断、端点、规则、调用图和执行流，问题可以定位到源码。
- 黑盒实际同源 HTTP 请求能够关联白盒端点及调用流，并明确区分唯一、歧义和未匹配结果。
- 联合结果持久化并形成可查询报告，不依赖进程内事件历史。

## 2. 范围与非目标

### 本期范围

1. 白盒任务的产品化输入、源码快照、可见性校验和异步分析进度。
2. 白盒结果语义补全、持久化和专用报告/控制台展示。
3. 黑盒同源 HTTP 请求证据采集。
4. 请求与白盒端点、调用流的确定性匹配。
5. 联合证据查询、报告和质量指标。

### 非目标

- 不把前端页面 URL 自动视为后端端点。
- 不采集认证头、Cookie、敏感请求体或跨域请求内容。
- 不因“端点未触达”自动判定任务或发布失败。
- 不在首期实现 Java 远端作业强制取消。
- 不无必要地破坏 Python↔Java HTTP 契约；新增白盒语义字段时必须同步两端 DTO/模型与契约测试。
- 历史任务、旧报告和测试数据不属于兼容范围，可按新模型直接重建。

## 3. 白盒能力补全

### 3.1 类型化任务配置

控制台、API 和 CLI 使用类型化白盒配置：源码来源、分支、分析 scope、目标模块和 Maven/classpath
选项。现有 `parameters` 输入只作为过渡读取路径；新建或编辑白盒任务必须经类型化字段校验和转换。

源码来源支持本地可见目录或 Git 仓库地址。仓库凭据不能写入 URL、任务参数、报告或日志，必须使用
部署环境提供的凭据机制。每次执行记录解析后的来源标识、分支和 Git commit SHA，形成不可变源码
快照标识。

容器部署在提交分析前验证 Python 与 Java 均能读取同一源码快照。验证失败时以稳定错误码终止，
不得将 Java 容器不可见的宿主机临时路径继续传入分析服务。

### 3.2 异步执行与取消

白盒执行改用 Java 异步作业接口：提交作业、轮询状态和事件，并将阶段、诊断与进度写入任务时间线。
轮询必须受任务超时、取消信号和客户端请求超时控制。

Java 当前没有远端取消接口。首版取消本地任务时停止继续轮询并标记“已停止等待，远端分析可能仍在
运行”，不能声称已终止 Java 作业。远端取消协议留到 Java 作业生命周期完善后单独演进。

### 3.3 结果语义与展示

白盒结果保留端点、调用图、执行流、聚类、诊断和原始规则标识。Python Finding 模型补充规则 ID、
规则类别和置信度等字段，不能再仅按严重级别推断 `security` 或 `functional`。

报告与控制台分别展示解析覆盖率、classpath 降级/失败诊断、端点清单、调用图/执行流，以及可定位
到源码的发现项。分析降级和部分解析失败必须醒目展示，不能把“有结果”误报为“完整分析成功”。

## 4. 黑白盒关联

### 4.1 联合分析边界

联合分析以同一项目和同一源码快照为边界，不让黑盒 Runner 直接依赖 Java 内部对象。一次联合分析
只创建一个不可变白盒快照；多个黑盒任务可复用该结果，避免重复扫描。未来接入回归批次时，由批次
先准备共享白盒快照，再执行关联黑盒用例。

### 4.2 黑盒请求证据

黑盒 Runner 采集同源 HTTP 请求的 HTTP 方法、规范化路径、响应状态和所属任务步骤，不记录认证头、
Cookie、敏感请求体或跨域请求内容。请求证据需要持久化，不能只保留在 Playwright 页面对象或日志中。

### 4.3 端点匹配

请求与白盒 `EndpointInfo` 按以下顺序匹配：

1. HTTP 方法与路径精确匹配。
2. HTTP 方法与路径模板匹配，例如 `/users/42` 匹配 `/users/{id}`。
3. 仅路径匹配，标记为低置信度候选。
4. 无候选时标记为未匹配。

多个候选必须标记为 `ambiguous` 并保留候选列表，不能生成虚假的唯一关联。匹配结果生成持久化的
`EndpointEvidence`，记录黑盒任务/步骤、请求证据、白盒端点、调用流、匹配状态、置信度和源码快照。

### 4.4 联合报告与质量信号

联合报告展示三类结果：黑盒实际触达的白盒端点及调用流、白盒发现项对应的黑盒触达证据、未触达
端点与未关联请求。白盒问题是否被黑盒触达不改变其原始严重级别。

端点未触达、关联歧义、classpath 降级和解析失败在首版均作为告警及报告质量指标，不自动阻断。
未来接入回归质量门禁时，新增高/严重白盒问题可按规则 ID 与规范化源码位置参与基线差异；是否将
覆盖率或关联质量设为门禁必须基于真实数据另行决策。

## 5. 持久化与接口

通过连续、幂等的 SQLite 迁移建立源码快照、白盒结构化结果、黑盒请求证据和 `endpoint_evidence`
（或职责等价的数据结构），并为项目、任务、源码快照和匹配状态建立索引。旧白盒结果和测试数据
可以直接重建，不要求兼容读取。

API 提供类型化白盒任务输入、分析进度、结构化结果、端点证据与联合报告查询。新增字段遵循现有
camelCase/OpenAPI 规范；Python↔Java 字段变更同步 Java DTO/Controller、Python client/model 和契约
测试。共享客户端、存储和协调服务只在 `RuntimeContainer` 装配。

## 6. 分阶段实施与验收

### 阶段一：白盒产品化

- 实现类型化配置、源码快照、跨进程可见性校验、异步作业轮询和真实取消语义。
- 验收：源码 commit 可审计；容器路径错误可诊断；进度进入任务时间线；测试数据可按新模型重建。

### 阶段二：白盒结果与界面

- 补全规则语义、诊断、持久化、白盒专用表单和结果页，同步 OpenAPI 类型。
- 验收：用户无需手填参数即可运行白盒任务，并能判断分析是否完整或发生降级。

### 阶段三：黑白盒关联

- 实现同源请求采集、端点匹配、`EndpointEvidence` 持久化和联合报告。
- 验收：精确、模板、低置信度、歧义和未匹配状态均准确且可追溯，不泄露敏感请求信息。

### 阶段四：验证

- Python：配置校验、源码快照、异步轮询、超时/取消、结果映射、请求脱敏和端点匹配测试。
- Java：DTO 契约、作业事件、分析降级和诊断测试。
- API/前端：白盒表单、进度恢复、专用报告、端点证据和联合报告测试。
- 端到端：本地源码、Git 源码、容器不可见路径、classpath 降级、模板路由、歧义路由和未匹配请求。

除非用户明确要求，不执行 Maven 编译 / 测试，由用户自行验证。

## 7. 风险与后续演进

- 动态路由、网关改写和非 HTTP 调用可能导致关联不完整：保留未匹配和歧义结果，不伪装为覆盖率或
  唯一调用链。
- 源码凭据、临时目录和容器挂载存在安全与拓扑风险：凭据只留在部署环境，执行前验证可见性，完成
  后按资源生命周期清理临时副本。
- Java 远端作业在 Python 取消后可能继续占用资源：首版明确状态，后续增加幂等取消接口和回收策略。
- 规则或源码位置不稳定可能影响基线比较：保留原始规则数据，收集样本后再调整规范化算法。
